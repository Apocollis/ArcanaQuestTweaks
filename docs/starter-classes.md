# Starter classes

Last updated: 2026-11-20. This file is shared by the starter class build forks: the server side (registry, lockdown, packets, commands) is documented by the module section; this page's **Client screen and art** section covers the screens and textures.

## Client screen and art

Code: `starter/client/` (client only). Plan: `.plans/archive/20261103-1255-starter-class-selection-gui.md` sections 12.8, 12.10 and 13.4 to 13.5.

**Entry points** (`StarterClientHooks`, all on the client thread; the starter packet handlers must call them from their client side only):

| Method | Effect |
| --- | --- |
| `open(intro, prompt, classes)` | Opens `GuiStarterClassSelection`. Ignored while the selection or the reveal is already open (the server re-sends the open packet every 100 ticks while pending). |
| `showResult(result)` | Opens `GuiStarterReveal`, cross-fading from the selection screen when that is open. |
| `closeAll()` | Closes whichever starter screen is open. |

**Selection screen** (`GuiStarterClassSelection`): panel with the intro (wrapped, config text), a divider, the prompt question in gold, a divider, then one row per class: a large icon (item stack scaled 2x, or a 32x32 emblem when the class icon is `tex:<namespace>:<name>`, resolved to `assets/<ns>/textures/gui/starter/<name>.png`), the class name and the memory text (wrapped). Intro, prompt and rows scroll together inside the panel (mouse wheel, arrow keys, Page Up and Down, scrollbar); the confirm line and **Select** button stay at the bottom. Layout is computed from the window size (panel at most 380x300, margin 8) and works at GUI scales 1 to 4. Gear, levels and the perk are not shown here. **Escape does not close it.** Select sends `PacketSelectStarterClass`; if no answer arrives within 100 ticks the button works again.

**Reveal screen** (`GuiStarterReveal`): "What you gained", the class title, the levels (`Attack IV`, Roman numerals), the perk (lang keys `aqtweaks.perk.<key>.name` and `.desc`) and the gear as item icons with tooltips (at most 12). It fades in over 10 ticks (cross-fading from the choice screen), holds until Continue, Enter or Escape or 240 ticks (12 s), fades out over 10 ticks, then sends `PacketStarterRevealDone` and closes. The server owns the real timeout.

**Pure logic** (`StarterClientMath`, `RevealTimeline`, tested): Roman numerals, the 12-item gear cap, scroll clamping, panel sizing, alpha colours (alpha below 4/255 would be drawn opaque by the font renderer, so text is skipped below 3%), scrollbar thumb, row lookup, and the reveal's fade in / hold / fade out state machine.

**Art.** All textures are in the mod jar under `assets/aqtweaks/textures/gui/starter/`, so the screens render the same with or without Stoneborn. They are drawn in the Stoneborn palette sampled from `STONEBORN-1.12.2-V3.1` (`generic_54.png`, `widgets.png`): outline `#000000`, highlight `#675D4E`, body `#4F473C`, shadow `#221E19`, inset `#151310`, button `#37322A`, gold `#BD862B`, dark gold `#493706`. Frames are nine-slice (`StarterDraw.nineSlice`).

| File | Size | Use |
| --- | --- | --- |
| `panel.png` | 64x64, corner 8 | main window, with gold filigree corners |
| `option.png`, `option_hover.png`, `option_selected.png` | 32x32, corner 6 | class rows and gear slots |
| `button.png`, `button_hover.png`, `button_disabled.png` | 32x20, corner 5 | Select and Continue |
| `divider.png` | 32x4 | stretched across the width |
| `class_warrior.png`, `class_archer.png`, `class_scout.png`, `class_miner.png`, `class_homesteader.png`, `class_scholar.png` | 32x32 | class emblems (heater shield & sword, bow & arrow, crossed daggers, socketed pickaxe, cottage with lit window and chimney smoke, open tome with ribbon) |

Regenerate the frames, buttons and divider with `powershell -ExecutionPolicy Bypass -File scripts\generate_starter_textures.ps1` (System.Drawing). The six class emblems are native 32x32 sprites generated by `python scripts/generate_starter_icons_32.py [--write]` (Pillow): shaded ramps in the perk-icon palette, top-left light, `#2b1d33` outline; running without `--write` updates only `.plans/assets/starter_icons_32_preview.png`, while `--write` overwrites the six `class_*.png` files (`scripts/generate_starter_icons.py` holds the earlier 16x16-at-2x pass). Edit the scripts, not the PNGs.

**Lang keys:** `aqtweaks.starter.select`, `.continue`, `.confirm` (`%s` is the class name), `.reveal.title`, `.reveal.levels`, `.reveal.perk`, `.reveal.gear`.

## Server module

Code: `starter/` (server side) and `network/PacketOpenStarterClassGui`, `PacketSelectStarterClass`, `PacketStarterClassResult`, `PacketStarterRevealDone`. Registered when Reskillable **and** CustomStartingGear (`customstartinggear`) are loaded (`CommonProxy.init`, `/aqclass` in `serverStarting`). CSG is compile-hard (`libs/CustomStartingGear-1.12-1.2.0.9-universal.jar`, copied by `build_gradle.ps1`). Plan: `.plans/archive/20261103-1255-starter-class-selection-gui.md` (12.x and 13.x are authoritative).

**What the player gets.** A new character is shown a story screen with six classes. The choice gives Reskillable skill levels, one class-exclusive free perk, a CSG kit and, for the Scholar, a console command. See the plan for the classes, levels (13.1) and memory texts (13.5).

**Config** `config/arcanaquesttweaks/aqtweaks_starter_classes.json`, server side only, written with defaults on first run and read lazily on the first login or `/aqclass` (skills, perks and CSG kits only exist once the game has loaded). The client never reads it.

| Key | Default | Meaning |
| --- | --- | --- |
| `intro` | the sanctuary / fall paragraph (plan 13.4) | Text above the options |
| `prompt` | `What's the last thing you remember?` | The question above the options |
| `showDetails` | `false` | Reserved test switch; the open packet does not carry skills or perk yet |
| `revealHoldSeconds` | `12` | How long the reveal panel waits for Continue; the server releases the player 5 s later if the client never answers |
| `classes[]` | six classes | `id`, `name`, `flavor` (the memory text), `icon` (`tex:aqtweaks:class_<id>` or an item id), `csg_kit`, `skills` (skill id to target level, raise only), `perk` (registry id of a class perk), `commands` (console commands, `%player%`) |

**Validation** (`StarterClassValidator`, pure, tested) runs at load and on `/aqclass reload`: duplicate or empty id, unknown `csg_kit`, unknown skill, non-positive level, a `perk` that is not a registered class perk (`ClassPerkSupport.isClassPerk`) or is already used by an earlier class, and **kit drift**: a kit must copy the default inventory's shared utility slots (main slots 8-11, 15-17, 27-35); slots 0-7 are free. An invalid class is left off the screen and logged as `[starter classes] class 'x': reason`. If no valid class remains, the lockdown is **not** applied and the menu is not shown, the pending flag stays set so the menu returns once the config is fixed, and an operator who logs in as a new character gets a red chat line.

**Who is prompted.** `StarterRules.shouldPrompt`: a chosen class never prompts again; a pending flag keeps prompting (a crash or a failed screen left it set); otherwise only a character without CSG's `csg:receivedInventory` flag is new, so characters that existed before this module are never asked. The login handler runs at HIGHEST priority, before CSG sets that flag. Persisted flags (survive death) in `PlayerPersisted`: `AQTStarterClassPending`, `AQTStarterClassChosen`, `AQTStarterClassId`.

**Presenting.** The open packet is sent 40 ticks after login, then every 100 ticks while the player is choosing, and again right after a respawn or dimension change. A client that already has the screen open ignores repeats. An open packet with an empty class list tells the client to close every starter screen.

**Lockdown** (`StarterLockdown`, session only, never saved). From login until the reveal ends the player is held at their login position, cannot be damaged or targeted, gets no potion effects, has full health, air and food each tick, cannot break or place blocks, interact, attack, pick up, toss or use items, and has any open container closed. Chat stays usable. `StarterLockdown.isLocked(player)` is the single predicate; it names no parent types. Guards (one early return) are in the per-player tick handlers of: Comfort (`ComfortSystemHandler.onPlayerTick`), Stamina (`StaminaModule.onPlayerTick`), Simple Difficulty (`SimpleDifficultyModule.onPlayerTick`), Somnia (`SomniaSleepHandler.onPlayerTick`) and the Thaumcraft module (`ThaumcraftModule.onPlayerTick`, the warp exposure). The hazard engine runs one timeline per world, not per player, so it has no guard: a locked player simply cannot be hurt by it.

**Reward** (`StarterReward`). On `PacketSelectStarterClass` the server re-validates the class, checks that the CSG kit and the skills exist (so a bad class changes nothing), then: raises the skills to the target level (raise only, capped at the skill cap), unlocks the class perk through `PlayerSkillInfo.unlock` (free), gives the CSG kit (`DataManager.givePlayerKit`, which clears the inventory first), writes the persisted flags, runs the class `commands` as the console (permission level 4, failures logged and never rolling the reward back), sets the Hearthkeeper flag on the home record when the perk is `hearthkeeper`, and sends `PacketStarterClassResult` (skills, perk key, kit minus the default items capped at 12, armor first). The player stays locked until `PacketStarterRevealDone` or `revealHoldSeconds + 5` seconds. An error before the flags are written keeps the player pending and locked with a red chat line.

**Login re-grant.** If a player with a stored class lost the perk (for example `/reskillable resetskill`), the next login gives it back.

**Commands** (`/aqclass`, OP level 2): `reload` (re-read and re-validate, prints errors), `skip <player>` (release without choosing, clears pending), `reset <player> confirm` (new character again; shows the menu), `regrant <player>` (give the class perk back), `info [player]` (valid classes, errors, and a player's flags).

**Packets** (discriminators 17-20): 17 `PacketOpenStarterClassGui` (client), 18 `PacketSelectStarterClass` (server), 19 `PacketStarterClassResult` (client), 20 `PacketStarterRevealDone` (server).

**Lang keys:** `aqtweaks.starter.nomenu`, `.failed`, `.chosen` (plus the client keys above).

**Tests:** `StarterClassValidatorTest`, `StarterSettingsIOTest`, `StarterKitDiffTest`, `StarterRulesTest` (prompt rule, send timing, reveal deadline, command substitution, lockdown membership).

**Files.** Server: `starter/StarterModule` (registration and events), `StarterClassDef`, `StarterClassRegistry` (the loaded classes), `StarterDefaults` (the six shipped classes and texts), `StarterSettings` / `StarterSettingsIO` (the JSON), `StarterClassValidator`, `StarterRules` (pure rules), `StarterState` (per-player chosen / pending flag), `StarterResult`, `StarterReward` (skills, perk, kit, commands), `StarterCsg` (Custom Starting Gear bridge), `StarterKitDiff`, `StarterLockdown` and `LockdownSet`, `StarterEnvironment` (what is loaded), `StarterClassView` (what the client is told), `CommandAqClass`. Perks: `reskillable/StarterClassPerks`, `StarterPerkMath`, `ClassPerkSupport`. Client: `starter/client/GuiStarterClassSelection`, `GuiStarterReveal`, `RevealTimeline`, `StarterClientHooks`, `StarterClientMath`, `StarterDraw`. Art: `scripts/generate_starter_textures.ps1` writes the frames, buttons and divider and `scripts/generate_starter_icons_32.py --write` writes the six native 32x32 class emblems under `assets/aqtweaks/textures/gui/starter/` (updated on 2026-11-20).

## Tabula Rasa (class reset item)

`aqtweaks:tabula_rasa` (display "Tabula Rasa", stack size 1, drinkable, 32 ticks) is registered when Reskillable and CustomStartingGear are loaded (`StarterItemRegistry`, `ItemTabulaRasa`). Drinking it runs `StarterResetService` on the server, in place (no damage, no death, no teleport):

- Every skill goes to level 1 and is respecced (`setLevel(1)` + `respec()`), which clears all perks including the class perk. The Hearthkeeper home flag, the perk toggle flags (`PerkToggleState.clearAll`) and cached levels are cleared and attributes refreshed.
- **XP refund:** only levels the player bought. For each skill the previous class's free target level (`def.skills`, capped at the skill cap, default 1 for an unknown class) is the base. Each step `lvl` to `lvl + 1` above the base refunds `ExperienceHelper.getExperienceForLevel(skill.getLevelUpCost(lvl))`. Free starter levels and the free class perk refund nothing. In creative mode nothing is refunded and the item is kept. Maths in `StarterResetMath` (unit tested).
- The player is locked where they stand and the class menu opens at once (`StarterModule.reawaken`) with `resetIntro` / `resetPrompt` from `aqtweaks_starter_classes.json` instead of `intro` / `prompt` (missing or blank values fall back to `StarterDefaults.RESET_INTRO` / `RESET_PROMPT`).
- The flag `AQTStarterClassNoKit` marks the reawakening: the next pick gives **no kit and no gear section**, skips all one-time `commands` except `tc research <player> add <KEY>`, which still runs when Thaumcraft is loaded and the player does not yet know that research (so a new Scholar gets `FIRSTSTEPS`). The flag is cleared after the pick, by `/aqclass reset` and by `/aqclass skip`; `/aqclass info <player>` prints `noKit=`.
- The drink is refused while a menu is open or the player is locked, or when no valid class exists (the item is not consumed).
- **Recipe:** a Thaumcraft Infusion (research `AQ_TABULA_RASA`, Alchemy tab at [-3, -6] under `SANESOAP`, file `assets/aqtweaks/research/tabula_rasa.json`), instability 4, aspects cognitio 40, permutatio 40, vacuos 30, spiritus 30, praecantatio 30. Catalyst `contenttweaker:life_elixir`; ring `thaumcraft:void_seed`, `botania:enderdagger`, `astralsorcery:itemshiftingstar`, `bewitchment:waystone`, `embers:intelligent_apparatus`, `da:aegyptia_metal_ingot`, `da:draugr_ingot`, `da:incendium_core`. If any item is missing, one warning is logged and neither the recipe nor the research is registered (`StarterThaumcraftHelper`, called from `ThaumAdditionsModule.init`). Model uses `aqtweaks:items/tabula_rasa` with enchantment glint (`hasEffect` returns `true`).

Client model registration for the item is `starter/client/StarterClientEvents.java`.
